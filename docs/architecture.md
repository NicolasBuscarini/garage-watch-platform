# Arquitetura local — T01

Este documento complementa, sem substituir, a arquitetura compartilhada em `../../docs/arquitetura/`. O fluxo implementado T01 é HTTP loopback → middleware de correlação/erro → query MediatR → Application → Domain, com `Infrastructure` implementando a porta de leitura do perfil via ambiente do host. O schema de resposta é versionado em `contracts/system-profile-response.v1.schema.json`. Domain/Application não referenciam HTTP nem infraestrutura; Host traduz o protocolo e faz composição.

O use case é somente leitura; não há banco/cache distribuído/broker/modelo ou adaptador de câmera/NAS ativo. T01-O acrescenta `OpenTelemetry` ao host: spans ASP.NET Core W3C e `use_case.execute`; métricas de execução/duração por caso de uso e meters ASP.NET/Kestrel/runtime .NET. Métricas customizadas usam tags estáticas `use_case` e `outcome`; não usam IDs por requisição, câmera/contexto, rota crua, texto da exceção nem payload. A correlação fica em logs/span tags, `trace_id`/`span_id` em escopo de log. OTLP HTTP-Protobuf (traces/métricas) só ativa com endpoint env válido; timeout e fila/lote do trace limitados; ausência/falha do backend não afeta resposta ou readiness. Headers de autenticação são injetados somente pelo ambiente protegido e nunca registrados. Exportação não é storage durável e nenhum dashboard/collector está incluído. O host dev roda em container loopback, sem mídia persistente. Câmera, vídeo, runtime de IA e armazenamento/NAS continuam fronteiras futuras; candidato documentado não significa adaptador ativo. Alterações de componentes/fluxos também atualizam o Mermaid canônico compartilhado.
