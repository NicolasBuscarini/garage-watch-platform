# Configuração e desenvolvimento

O ambiente de desenvolvimento deve ser executado via Docker Compose. Copie `.env.example` para `.env` e ajuste `APP_UID`, `APP_GID` aos IDs do usuário local e `APP_PORT` se necessário. O `.env` é ignorado. O serviço é publicado somente no loopback (`127.0.0.1`), usa imagem oficial .NET SDK `10.0.403` por digest, FFmpeg Ubuntu `7:6.1.1-3ubuntu5`, usuário não-root, `no-new-privileges`, capacidades removidas e tmpfs limitado. O spool T02 é persistido no bind mount local ignorado `./data`; nenhum segredo de produto é versionado. Pull da imagem, restore e pacotes do sistema dependem de MCR/NuGet/Ubuntu archives. NuGet usa lockfiles/hash; o pacote FFmpeg está fixo por versão Debian, mas suas dependências de sistema vêm do repositório Ubuntu sem snapshot imutável. Esse tráfego é de ferramentas/pacotes, não de mídia/pessoas.

Os lockfiles `packages.lock.json` estão versionados. Comandos: `docker compose build`; restore travado `docker compose run --rm api dotnet restore GarageWatch.slnx --locked-mode`; teste `docker compose --profile test run --rm test`; execução `docker compose up --build`. Ao alterar dependências, atualizar e revisar lockfiles explicitamente antes do commit. Nenhuma instalação de SDK no host nem acesso à câmera/NAS é necessário. Todo ambiente é injetado; não adicionar connection strings, tokens ou senha ao Compose.

Variáveis: `APP_PORT` (8081 por padrão), `APP_UID` e `APP_GID` (1000 por padrão); `AUTH_USERNAME`, `AUTH_PASSWORD` (mínimo 6 caracteres; placeholder recusado) e `AUTH_ROLE` (`Administrator` ou `Viewer`); `OTEL_EXPORTER_OTLP_ENDPOINT`/`OTEL_EXPORTER_OTLP_HEADERS`; e variáveis T02 em `capture.md`. O mínimo de seis caracteres foi autorizado pelo operador para uso local e é fraco para segurança; prefira senha mais longa, exclusiva e aleatória. Credenciais ficam em `.env` ignorado ou ambiente protegido, nunca no arquivo versionado. A conta é única, local e dev-only; a senha não é persistida. Cookies expiram em 8 h, não deslizam, são HttpOnly/SameSite Strict, e reiniciar o host invalida as sessões. Login é limitado a cinco tentativas por minuto no processo. O painel registra presença aproximada por aba autenticada: UUID aleatório só em memória no browser, heartbeat a cada 10 s, lease de 30 s e capacidade de 64 clientes no processo; sem lista de usuários/IPs e sem persistência. Abas suspensas ou fechadas podem continuar no número até expiração, e restart zera a contagem. Como o bind de desenvolvimento é HTTP loopback, `Secure` acompanha o esquema da requisição; não exponha o serviço na LAN nem use essa autenticação em produção. O player usa bundle HLS.js local fixado em 1.7.3, sem CDN ou conexão externa em runtime; configuração de buffer limita memória de mídia, mas latência/CPU continuam sem benchmark. A exportação OTLP usa HTTP-Protobuf, timeout de 3 s, fila de spans 256, lote de 64, intervalo de 5 s e request máximo de 1 MiB. Falha do collector não altera resposta/readiness; não há retry síncrono ou durabilidade. `localhost` dentro do container refere-se ao próprio container. Health e telemetria não expõem configuração sensível.
