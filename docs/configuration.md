# Configuração e desenvolvimento

O ambiente de desenvolvimento deve ser executado via Docker Compose. Copie `.env.example` para `.env` e ajuste `APP_UID`, `APP_GID` aos IDs do usuário local e `APP_PORT` se necessário. O `.env` é ignorado. O serviço é publicado somente no loopback (`127.0.0.1`), usa imagem oficial .NET SDK `10.0.403` por digest, usuário não-root, `no-new-privileges`, capacidades removidas e tmpfs limitado. Não tem volume persistente nem segredo de produto. Pull da imagem e primeiro restore dependem de acesso a MCR/NuGet; versões transitivas são travadas por lockfiles e hash. Esse tráfego é de ferramentas/pacotes, não de mídia/pessoas.

Os lockfiles `packages.lock.json` estão versionados. Comandos: `docker compose build`; restore travado `docker compose run --rm api dotnet restore GarageWatch.slnx --locked-mode`; teste `docker compose --profile test run --rm test`; execução `docker compose up --build`. Ao alterar dependências, atualizar e revisar lockfiles explicitamente antes do commit. Nenhuma instalação de SDK no host nem acesso à câmera/NAS é necessário. Todo ambiente é injetado; não adicionar connection strings, tokens ou senha ao Compose.

Variáveis: `APP_PORT` (8081 por padrão), `APP_UID` e `APP_GID` (1000 por padrão; ajustar ao usuário do host para escrita dos artefatos de build no bind mount); `OTEL_EXPORTER_OTLP_ENDPOINT` (vazio por padrão; URI HTTP(S) absoluta do backend/collector OTLP, sem userinfo, query ou fragmento) e `OTEL_EXPORTER_OTLP_HEADERS` (vazio; headers de autenticação secretos quando necessários, somente em `.env` ignorado/ambiente protegido). A exportação usa HTTP-Protobuf para traces e métricas. Endpoint inválido falha no startup sem ser ecoado; ausente significa exportação desabilitada. Timeout é 3 s; fila de spans tem 256 itens, lote de 64, intervalo de 5 s e request limitado a 1 MiB. Exportação funciona em background e perda/indisponibilidade do collector não altera a resposta/readiness; não há retry síncrono nem garantia de durabilidade. O endereço precisa ser acessível de dentro do container; `localhost` refere-se ao próprio container. `ASPNETCORE_ENVIRONMENT=Development` e endereço interno do container são valores fixos do perfil local, sem configuração de produção. Health detalhado e `/metrics` não foram adicionados; nenhum endpoint de backend externo é publicado pelo Compose.
