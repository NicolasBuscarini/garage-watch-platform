# Configuração e desenvolvimento

O ambiente de desenvolvimento deve ser executado via Docker Compose. Copie `.env.example` para `.env` e ajuste `APP_UID`, `APP_GID` aos IDs do usuário local e `APP_PORT` se necessário. O `.env` é ignorado. O serviço é publicado somente no loopback (`127.0.0.1`), usa imagem oficial .NET SDK `10.0.403` por digest, FFmpeg Ubuntu `7:6.1.1-3ubuntu5`, usuário não-root, `no-new-privileges`, capacidades removidas e tmpfs limitado. O spool T02 é persistido no bind mount local ignorado `./data`; nenhum segredo de produto é versionado. Pull da imagem, restore e pacotes do sistema dependem de MCR/NuGet/Ubuntu archives. NuGet usa lockfiles/hash; o pacote FFmpeg está fixo por versão Debian, mas suas dependências de sistema vêm do repositório Ubuntu sem snapshot imutável. Esse tráfego é de ferramentas/pacotes, não de mídia/pessoas.

Os lockfiles `packages.lock.json` estão versionados. Comandos: `docker compose build`; restore travado `docker compose run --rm api dotnet restore GarageWatch.slnx --locked-mode`; teste `docker compose --profile test run --rm test`; execução `docker compose up --build`. Ao alterar dependências, atualizar e revisar lockfiles explicitamente antes do commit. Nenhuma instalação de SDK no host nem acesso à câmera/NAS é necessário. Todo ambiente é injetado; não adicionar connection strings, tokens ou senha ao Compose.

Variáveis: `APP_PORT` (8081 padrão), `APP_UID`/`APP_GID` (1000 padrão), `IDENTITY_DB_PATH` (arquivo SQLite absoluto; Compose usa `/data/identity/garagewatch.db`), `AUTH_USERNAME`/`AUTH_PASSWORD` (bootstrap somente quando o banco não possui contas; mínimo 12 caracteres), `AUTH_EMAIL` (e-mail opcional do primeiro administrador, ainda sem fluxo de verificação/notificação), `OTEL_EXPORTER_OTLP_ENDPOINT`/`OTEL_EXPORTER_OTLP_HEADERS` e variáveis T02 em `capture.md`. O placeholder do exemplo é rejeitado. Bootstrap sempre cria Administrator; `AUTH_ROLE` não é mais usado. Alterar variáveis depois que existe usuário não troca identidade/credencial. SQLite é a fonte durável de usuário/roles/grants/auditoria; migrations rodam antes do tráfego, falha interrompe startup. No Linux, diretório/banco têm modos 0700/0600; banco fica no volume ignorado `data/`, sem backup/restore coberto nesta tarefa. ASP.NET Core Identity usa hash padrão versionado, lockout após cinco falhas por 15 min e requer 12 caracteres; rate limiter de login também limita cinco tentativas/minuto globalmente no processo. O cookie dura 8 h, não desliza, é HttpOnly/SameSite Strict; SecurityStamp é validado a cada 15 s no máximo e mudanças IAM o atualizam; Data Protection key segue efêmera e restart revoga sessões. Perfil exclusivamente dev/loopback, sem LAN, TLS/keyring durável ou UI de cadastro/admin. O painel mantém papel existente Administrator/Viewer; User/grants por câmera ainda não têm fluxo de UI nem enforcement completo. Presença, player e limites OTLP seguem como descritos adiante; sem alegações de latência/CPU homologadas.
